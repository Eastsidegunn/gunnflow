# 보기 셋 — 지금(목록) · 주변(선택 그래프) · 지도(컨테이너 지도) — 기능·시나리오

문제: 전체 그래프가 기본 보기다. 노드가 수십~수백 개면 멀리서는 글씨도 정보도 없고, 사람은
"지금 내가 뭘 해야 하지?"를 그래프를 훑어서 스스로 찾아야 한다. 노드 라벨은 긴 문장이라
멀리서 읽히지 않고, 무엇이 살아 있고 무엇이 바뀌었는지는 화면에 없다.

계약 0.6.0이 노드에 선택 필드(shortName · summary · active · lastActivityTs ·
changedAtRevision · originNodeId · steps)를 더했다. 이 문서는 그것을 쓰는 보기 셋을 정한다.
필드가 하나도 없는 백엔드에서도 세 보기는 동작한다. 그 경우 해당 장식만 빠진다.

## 0. 인간공학 근거 — 사람이 하루에 하는 일 셋

조종석에 오는 사람의 질문은 셋이고, 각각 필요한 정보량과 시선이 다르다.

| 질문 | 필요한 것 | 그래프가 맞나 |
|---|---|---|
| **"지금 내 몫은?"** (하루 대부분) | 나를 기다리는 것, 움직이는 것. 몇 개, 무엇, 얼마나 됐나 | 아니다. 순서 있는 **목록**이 맞다. 위→아래 한 번 훑기로 끝나야 한다 |
| **"이건 무엇과 얽혀 있나?"** (항목 하나를 판단할 때) | 그 노드 + 바로 이웃 + 어디 속하나 | 맞다. 단, **작은** 그래프여야 한다(10~30노드). 글이 읽히는 배율 |
| **"전체가 어디로 가고 있나?"** (가끔, 방향 확인) | 큰 덩어리들, 각각의 진척과 최근 변화 | 지도가 맞다. 멀리서는 색·크기·뱃지가 정보이고 글은 짧은 이름뿐이다 |

지금의 전체 그래프는 세 질문 모두에 어중간하다. 첫 질문에는 너무 많고, 둘째에는 이웃이
묻히고, 셋째에는 덩어리가 아니라 낱개가 보인다. 그래서 질문마다 보기 하나를 준다.

- **시선**: 보기 A는 왼쪽 위에서 시작해 아래로만 읽는다(목록 문법). 보기 B는 선택한 노드가
  화면 중앙에 오고, 이웃은 그 둘레에 놓인다. 시선은 중앙에서 한 걸음만 나간다.
- **손**: A에서는 ↑↓와 Enter만으로 일을 끝낼 수 있다. B로 들어가는 것은 Enter나 클릭 한 번,
  돌아오는 것은 Esc 한 번이다. C는 마우스로 훑어보는 보기다(줌·팬). 더블클릭하면 그 덩어리의 B로 간다.
- **주의 전환**: 보기 사이 이동은 "같은 노드를 다른 거리에서 본다"는 문법으로 통일한다.
  A의 항목 → B의 중앙 노드 → (Enter) 기존 ② 스테이지/③ 작업 표면. 어디서 왔는지는 화면
  상단의 경로 한 줄(`지금 › 주변: <이름>`)이 항상 말해 준다.
- **네트워크 0**: 보기 전환·줌·펼치기는 이미 받은 스냅샷만 쓴다. 백엔드 요청은 스냅샷 수신,
  '보내기', 그리고 상세 첫 열기 1회(같은 revision 동안 로컬 보관)뿐이다.

## 1. 보기 A — 지금 (기본 랜딩)

첫 화면. 그래프가 없다.

```
┌ 지금 ─────────────────────────────── 지도 · 전체 ┐
│ 나를 기다림 3                                     │
│  ▸ 결정 요청 (2)                                  │   ← attention 무리(wiring group), 무리 안은 since 오래된 순
│     ● <shortName|label>   · 2시간 전 · <summary>  │
│     ● …                                           │
│  ▸ 막힘 (1)                                       │
│     ● …                                           │
│                                                   │
│ 움직이는 중 5                                     │   ← active === true, lastActivityTs 내림차순
│     ◉ <이름>  ▮▮▮▯▯ 3/5  · 4분 전 · <summary>     │   ← steps 있으면 막대+숫자
│     ◉ …                                           │
│                                                   │
│ 바뀜 (지난 확인 이후) 7          [모두 봤음]      │   ← changedAtRevision > lastSeen, 최근 revision 순
│     △ …                                           │
└───────────────────────────────────────────────────┘
```

- **나를 기다림**은 attention 항목이다(기존 GF-P1의 무리·순서를 그대로 쓴다). 주의 부품
  불변식대로 렌즈·필터가 이 칸을 숨기지 않는다.
- **움직이는 중**은 `active === true`인 노드다. active가 없는 노드는 넣지 않는다(없음 = 모름).
  lastActivityTs가 없으면 맨 뒤에 id 순으로 둔다. 시각은 상대시간으로 보이고, 툴팁에 절대 시각이 있다.
- **바뀜**은 `changedAtRevision > lastSeenRevision`인 노드다. 이것은 뷰 지위다. 목록 머리에
  "지난 확인 이후"를 표기한다. [모두 봤음]을 누르면 lastSeen이 현재 revision으로 올라간다.
  자동으로 올리지 않는다. 자동으로 올리면 사람이 보지 않은 변화가 사라진다.
- 세 칸 모두 비면 정직하게 "기다리는 것 없음 · 움직이는 것 없음 · 바뀐 것 없음"이라고 보이고,
  그 아래에 지도·전체로 가는 버튼을 둔다.
- 백엔드가 active·changedAtRevision을 하나도 주지 않으면 그 칸 대신 "이 백엔드는 활동/변화
  정보를 보내지 않는다" 한 줄을 보인다. 빈 정상 목록처럼 보이게 하지 않는다(불변식 2).
- 한 행 = 상태 글리프 · 이름(shortName → label → id) · 시각 · summary 한 줄(말줄임).
  summary는 수신 텍스트이므로 평문으로만 보인다.
- **조작**: ↑↓로 이동하고, Enter·클릭이면 그 노드의 보기 B로 간다. 결정 요청 항목에서
  `D`를 누르면 기존 결정함이 그 항목에서 열린다(결정함은 그대로 둔다).

## 2. 보기 B — 주변 (선택 노드 중심의 작은 그래프)

```
┌ 지금 › 주변: <이름> ─────────────────────── Esc ┐
│  경로: <최상위> › <중간> › <이름>               │   ← 포함 조상 경로(빵부스러기, 클릭=그 노드의 B)
│                                                 │
│        [waits_on]          [produces]           │
│      ○ A ──────▶ ● <선택> ──────▶ ○ X           │   ← 관계 1단계만. 역할(wiring role)별로 방향 묶음
│      ○ B ──────▶   │                            │
│                    ◂ 출처: <origin>             │   ← originNodeId: 선 아님, 한 줄 칩
│   (포함된 자식은 선택 노드 박스 안에 접힘 N)     │
└─────────────────────────────────────────────────┘
```

- 그리는 것: 선택 노드 + 수신 관계로 1단계 닿는 노드(들어오는 것·나가는 것) + 포함 조상
  경로. 그 밖은 그리지 않고, "이 보기에 없는 노드 N개"를 머리에 표기한다(숨김 개수 표시 의무).
- 관계 역할이 wiring에 있으면 이웃을 역할별로 묶어 놓는다. `waits_on`·`blocks`는
  왼쪽(선택을 막는 쪽)과 오른쪽(선택이 막는 쪽)에, `produces`는 오른쪽에, `supports`는 아래에
  둔다. 역할이 없으면 기존 배치(ELK)를 쓴다. 배치는 local-only이고 의미가 없다.
- 줌 사다리·닻(GF-P1b C)을 그대로 쓴다. 첫 프레임은 "전부 맞춤" 닻이다.
- 선택 노드를 클릭하면 기존 ② 스테이지가 열리고, Enter를 누르면 ③ 작업 표면이 열린다.
  이웃을 더블클릭하면 그 이웃이 새 중앙이 된다(B 안에서 걸어 다니기). 경로 줄은 걸어 온
  자취를 최대 5개까지 보인다.
- Esc를 누르면 온 곳(A 또는 C)으로 돌아간다. 돌아가면 그 목록 위치나 지도 카메라가 그대로다.

## 3. 보기 C — 지도 (최상위 컨테이너만)

```
┌ 지도 ───────────────────────────── 지금 · 전체 ┐
│  ┌──────────────┐  ┌───────────┐  ┌─────────┐ │
│  │ <shortName>  │  │ <short>   │  │ <short> │ │   ← 깊이 0~1 컨테이너만. 상태색 = wiring 상태색
│  │ ▮▮▮▮▯ 12/15  │  │ ▮▯▯ 1/3   │  │         │ │   ← steps 뱃지(있을 때만)
│  │ △ 변화 4     │  │           │  │ ● 2     │ │   ← 안에서 변화 N(뷰 계산) · 기다림 N(attention)
│  └──────────────┘  └───────────┘  └─────────┘ │
└────────────────────────────────────────────────┘
```

- 그리는 것: 포함 깊이 0~1의 컨테이너(자식이 있는 노드)와 그 사이 관계선(역할 있는 것)이다.
  안쪽 노드는 그리지 않고, 개수만 박스에 적는다.
- 라벨은 shortName이다. 없으면 label 앞 24자 + `…`로 보인다.
- **변화 N**은 컨테이너 안(수신 포함 관계로 닿는 자손) 중 changedAtRevision > lastSeen인 노드
  수다. 이것은 뷰 계산이고, 표기는 "변화"(수신 사실처럼 "업데이트됨"이라고 쓰지 않는다)로 한다.
  컨테이너 자기 변화는 박스 테두리 강조로 따로 보인다.
- **기다림 N**은 안쪽 attention 수다. 주의 부품 불변식대로 지도에서도 숨지 않는다.
- 더블클릭하면 그 컨테이너의 B로 간다. 휠·핀치 줌과 가운데 드래그 팬은 기존 입력 규약 그대로다.

## 4. 전체 (메뉴로만)

지금의 전체 그래프는 사라지지 않는다. 기본에서 빠질 뿐이다. 상단의 `전체`를 누르면 지금
그대로의 캔버스(①②③, 결정함, 개인 층)가 열린다. 렌즈 사이드바도 이 보기에만 있다.

## 5. 상태와 저장

- 현재 보기(A/B/C/전체)와 B의 중앙 노드·자취는 `WorkspaceViewState`(local-only)에 둔다.
- lastSeenRevision은 기기 prefs에 둔다. 키는 (actor × upstream URL)이다. 상류 revision이
  lastSeen보다 작아지면(백엔드 재구축) lastSeen을 현재 값으로 리셋하고 변화 표시는 하지 않는다.
- 상세(detail)는 첫 열기 1회만 받고, 같은 revision 동안 다시 받지 않는다.
- 첫 화면 설정: prefs `landingView`(기본 `now`). 사람이 `전체`를 기본으로 되돌릴 수 있다.

## 6. 불변식 접점

모든 행·박스는 수신 projection의 반영이다. "바뀜", "변화 N", "이 보기에 없는 노드 N"은 뷰
지위로 표기한다. 진척은 steps가 있을 때만 보이고, 엔진이 자식 수로 계산하지 않는다. 주의
항목은 어느 보기에서도 숨지 않는다. 보기 조작은 네트워크 요청 0이다(e2e에서 요청 수를 단언한다).

## 7. 결정된 선택지 (ops 2026-10-11 — [H]는 실제 화면으로 검수)

- (a) A의 세 칸 순서 = **기다림 → 움직임 → 바뀜**.
- (b) B에서 노드를 열면 **그 노드만** 봤음 처리한다(그 노드의 changedAtRevision까지). 수동
  [모두 봤음]도 유지한다. 따라서 lastSeen은 전역 revision 하나와 노드별 예외 집합으로 이뤄진다.
- (c) B 역할 배치 = **좌 = 선택을 막는 쪽(blocks 들어옴·waits_on 나감) · 우 = 선택이 막는 쪽·산출(blocks 나감·produces) · 아래 = 지원(supports)**.
- (d) C의 깊이 = **0~1이 기본**. 최상위(깊이 0) 노드가 30개를 넘는 작업공간은 깊이 0으로 시작한다.
- (e) PR은 A → B → C를 하나씩 낸다. A만 머지된 동안 A의 항목 Enter는 전체 그래프의 ② 선택으로 간다.
- 목업은 만들지 않는다. [H]가 실제 화면으로 검수한 뒤 머지한다.
- (2026-10-11, A 구현) 구현이 문서와 다른 점: ① 기다림 무리 안의 순서는 결정함 로직을 그대로 써서
  수신 순서다(§1 그림의 "since 오래된 순"이 아님 — 결정함과 갈라지지 않게). 행이 없는 무리는 지금
  목록에 싣지 않는다. ② lastSeen은 prefs 파일이 아니라 브라우저 localStorage에 둔다(봤음 표시가
  요청 0이 되도록). 키는 BFF가 이미 알려 주는 상류 이름(`/api/upstream` label)이고, actor는 이
  브라우저 프로필이다(조종석에 actor 신원이 아직 없다). 이 상류에 대한 기록이 없는 첫 방문이면
  전역 표시를 그때의 현재 revision으로 시작하고 바뀜 칸에 "첫 확인 — 이후 바뀐 것부터 보인다"를
  보인다(자동 올림이 아니다 — 잴 수 있는 이전 확인이 없다). 상류 이름을 모르면 표시는 메모리에만
  두고 저장하지 않으며(공용 대체 기록 없음), 새로고침하면 사라진다고 바뀜 머리에 적는다. revision이
  전역 또는 노드별 표시 중 어느 것보다 작아지면 리셋한다. ③ 보기 전환 키는 설정 항목 `switch-view`(기본 `V`), 목록 이동은
  ↑↓와 결정함과 같은 바인딩(`inbox-next`/`inbox-prev`, 기본 J/K)이다.
- UI strings via catalog, en default, ko translation (2026-10-11, [H]). 지금 보기의 글은 모두 카탈로그 키(`view.*`, `now.*`, `settings.prefs.landing*`)이고, 개수가 든 머리는 단·복수 형태(`tn`)를 쓴다.
