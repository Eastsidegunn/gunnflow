# 동적 뷰 P3 — 공간(크기)·전환 애니메이션: 기능·시나리오

정본: docs/recharter/dynamic-view-design.md. P1(배치)·P2(tier→강조·디테일)는 landed.
P3 = 세 번째 출력(공간) + "지오메트리는 전환 순간에만" 규칙의 애니메이션 구현.

## 1. 기능 정의

- **크기 = tier의 공간 표현**: tier 높은 노드가 더 큰 박스를 받아 디테일(라벨·부품)을
  수용한다. 크기는 레이아웃 입력 — 전환 순간의 재배치에서 자연스럽게 여유가 배분된다.
- **지오메트리가 변하는 유일한 순간**: 토폴로지 변화 / lens 변경 / sort key 변경(P4 대비
  이음새만) / 명시 tidy(fit·재정렬). 그 외에는 위치가 튀지 않는다.
- **포커스 전환은 국소만**: 선택·열람으로 tier가 바뀌면 그 노드가 커지고, 이웃을 밀어내
  **커진 노드 둘레에 여백까지 확보**한다(확정 — 겹침 해소 최소가 아님. 근처 이웃은
  더 움직여도 되지만 여전히 국소 파급이지 전면 reflow가 아니다). 드래그 핀 노드는
  **밀리지 않는다**(위치 불가침). 단 크기는 핀도 tier를 따른다 — 커진 노드를 드래그할 때
  박스가 커서에서 이탈하지 않아야 하므로(인간공학 기준).
- **크기를 움직이는 신호는 사람의 것만**: 전환 순간 사이에 지오메트리(크기·밀어내기)를
  바꾸는 tier 변화는 **사람이 일으킨 것**(선택·열람·pending intent와 그 1-hop 파급)뿐이다.
  수신 사실만으로 생기는 tier(attention 도착, 최근 수신 변경·감쇠, lens 매치)는 전환
  순간 사이에는 강조·디테일(P2)에만 작용하고, 크기는 다음 전환 순간에 일괄 반영된다 —
  백엔드 갱신·타이머만으로 캔버스가 재배치되지 않는다("지오메트리는 전환 순간에만"의
  일관 적용). 국소 겹침·그룹 겹침 안착 금지는 전 경우 동일.
- **보강 규칙**:
  - 사람 원인 tier의 1-hop 파급 집합은 **사람 행동 시점에 스냅샷**된다 — 이후 수신으로
    relation이 추가되어도 다음 사람 행동·전환 순간까지 집합이 늘지 않는다(수신 사실이
    전환 없이 지오메트리를 움직이는 통로 차단). pending intent의 확정에 따른 축소는
    사람 제스처 수명의 완결로 보고 허용한다.
  - **국소성은 레벨 단위로 센다**: 강체로 밀린 형제 컨테이너는 그 레벨에서 인접 1-unit
    이동이고, 멤버가 함께 타는 것은 응집 이동(산개가 아님)으로 허용한다.
  - **고정은 leaf 단위다, 컨테이너 단위가 아니다**: 핀·포커스 leaf만 불가침이고,
    컨테이너 wrap은 파생물로서 변형·이동 가능하다. 사람 고정 leaf끼리의 겹침(포커스
    박스 아래 핀)만 유일한 허용 겹침이고, 엔진이 움직일 수 있는 지오메트리끼리는
    어떤 경우에도 겹쳐 안착하지 않는다 — 막히면 여백을 압축해서라도 푼다.
- **단순화 규칙**: 전환 사이의 국소 성장은
  **국소 여유(slack) 안에서만** 일어난다. 이웃 밀기는 같은 컨테이너의 형제와 자유 공간
  (어느 컨테이너의 영역도 아닌 곳)에 한하고, 컨테이너 wrap은 자유 공간으로만 자란다.
  여유가 모자라면 **크기가 양보한다**(목표 1.6×에 못 미쳐도 됨 — 겹침·원거리 이동·타
  컨테이너 변형으로 공간을 만들지 않는다). 완전한 크기는 다음 전환 순간의 전체 재배치가
  준다("공간 재분배는 전환 순간"의 일관 적용). 이로써 겹침 금지·국소성·핀 불가침·포커스
  불변이 해법의 성질이 아니라 **구성상 보장**이 된다. "여백까지 확보" 결정은 이
  여유 안에서 최대한 적용한다(여백 우선, 압축은 마지막).
- **모든 변화는 애니메이션**: 현재→목표 rect 보간(테마 모션 토큰). **전환 애니메이션 중에도
  즉시 조작 허용**(확정 — 잠금 없음, 애니는 따라온다). 따라서 중간 프레임에서도
  히트테스트는 화면에 보이는 지오메트리 그대로. 어떤 경우에도 겹침 없는 상태로
  안착(불변식 테스트).
- tier는 순서에 관여하지 않고(P4), tier0은 dim까지(§11, 확정).

## 2. 사용자 시나리오

1. 사용자가 노드 A를 클릭 → A가 0.24s에 걸쳐 한 단계 커지며 디테일이 늘고, 근처 이웃들이
   밀려나 A 둘레에 여백이 생긴다(여백 확보까지가 목표 — 겹침만 푸는 게 아니다). 파급은
   국소에 그치고, 먼 노드들은 움직이지 않는다. 밀려나는 중에도 사용자는 바로 다른 노드를
   클릭하거나 pan할 수 있다 — 애니메이션이 조작을 막지 않는다.
2. A의 1-hop 이웃(tier2)은 이미 P2대로 강조·디테일이 올라가 있고, 크기는 중간 단계.
3. 사용자가 lens를 "plan"으로 바꿈 → **전환 순간** — 전체 레이아웃이 새 크기 분포로 재계산되고,
   모든 노드가 0.4s 애니메이션으로 새 자리로 흘러간다(사라지는 것 없음, dim만). 흘러가는
   중에도 조작은 즉시 먹는다(확정 — 잠금 없음).
4. 백엔드에서 새 노드가 생김(토폴로지 변화) → 기존 stabilize 규칙대로 전환, 신규 노드는
   바깥에서 들어오는 모션(기존 등장 문법 유지).
5. 사용자가 노드 B를 드래그해 고정 → 이후 어떤 전환·밀어내기도 B를 움직이지 않는다.
   핀 해제는 명시 행동.
6. 선택 해제 → A가 원래 크기로 줄고, 밀려났던 이웃이 제자리로 돌아온다(대칭).

## 3. 설계 결정

- (a) tier별 크기 = **tier3 1.6× / tier2 1.25× / tier1·0 1×** (초안대로).
- (b) 밀어내기 범위 = **여백까지 확보** — 커진 노드 둘레에 여백. 이웃이 더 움직여도 된다.
- (c) 전환 애니 중 입력 = **즉시 조작 허용** ("안착까지 잠금"안은 채택하지 않음).
