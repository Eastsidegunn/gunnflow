# Gunnflow 0.1.0 — release notes (draft)

Status: **draft, unreleased.** Alpha.

Gunnflow is a backend-agnostic human cockpit: a node-relation visualization and manipulation
engine for systems whose meaning lives in a backend. It reflects received state, relays human
actions as intents, enforces decision procedures, isolates agent artifacts and delivers
attention. Vocabulary comes from data-only wiring config.

## Highlights

- **One wire, any backend.** A backend connects by serving the HTTP endpoints in
  [packages/contract/WIRE.md](../../packages/contract/WIRE.md) and pointing one config line at it.
  No plugin, no code loading.
- **Contract `@gunnflow/contract`**, with nodes, streams, intents, artifacts, node detail and
  execution surfaces, runtime validators and a conformance suite backends run in their own CI.
  The contract went through 0.2.0 (node detail) and 0.3.0 (execution surface) during
  development; these are not described as published releases here.
- **Cockpit depth model and decision inbox.** Overview → selection stage → full work surface
  (Esc steps back), and a queue for pending decisions with interrupts first.
- **Dynamic view (P1–P3).** Relevance tiers from explicit signals drive emphasis, detail and
  size. Geometry changes only at transitions, and growth stays inside local slack.
- **Honest by construction.** Screen grades (assured / claim / portal / draft / personal),
  isolated viewers on a separate origin, unsupported surfaces stated as unsupported, unknown
  vocabulary shown undistorted.

## What works

- End to end against the in-repo simulator (`testing/fake-contracts`) and the reference
  direct-wire server. Any backend implementing `packages/contract/WIRE.md` can connect through the
  `direct` upstream; an adapter maintained outside this repository is not verifiable here.
- Generic node assembly from wiring parts, multi-file wiring merge, literal render vocabulary.
- Intent relay with the full pending lifecycle; rejection returns input to the human.
- Digest-addressed artifacts re-verified on the isolated origin; sandboxed HTML/SVG, images,
  Excalidraw, download fallback; explicit-open live portals.
- Local-only personal layer (notes, stickies, planning board).
- Tooling: `pnpm verify`, Playwright e2e on simulator and direct paths, `pnpm render-sweep`
  vocabulary audit against a live wire.

## Known limitations

- **Streams are simulator-only.** The append-stream contract (contiguous sequence, resume cursor,
  input reference for stdin attribution, idempotency-key acceptance on the wire) is still pending
  upstream. The stream and live-terminal parts run against the fake backend
  only.
- **Edit intents** need an upstream `edit` capability and a digest-bytes convention;
  first-class emission of capability, attention and state vocabulary is still requested from upstream.
- **Execution surface:** the contract carries no event payloads. A payload surface is future
  work. Session fields that are carried but not yet shown, the per-frame validation cost during
  bursts, and a control-character policy for `kind` / `label` are deferred. In live mode the
  execution surface has no entry point yet. Its only entry is the domain inspector, which live
  projections do not reach.
- **Node detail:** once the cockpit sees `501` (surface unsupported) it does not reset that state
  when the upstream reconnects. Switching nodes can fetch twice, and there is no refetch option when the projection
  revision moves past the detail's revision.
- **Mermaid:** a renderer port exists, but no renderer is wired by default, so Mermaid surfaces
  show as unavailable.
- **Authentication:** no identity provider is wired yet. The BFF currently uses the fixed
  development actor `fake-actor:local-dev` ([BLOCKED.md](../../BLOCKED.md) §4). Keep the dev
  servers on localhost.
- **Deliverable declaration** and full execution telemetry (event detail, PTY, runtime context)
  remain blocked on upstream contracts ([BLOCKED.md](../../BLOCKED.md) §1–2).
- Copilot drafting is designed but not implemented. It is waiting on design decisions about
  process, consent and storage.
- `render-sweep` does not include the engine's built-in default wiring, so it may over-report.
- Solid components have no DOM-level unit tests. UI behaviour is covered by e2e.
- Design records in `docs/` are mostly in Korean.

## How to try it

```sh
# Node 22+, pnpm 10
pnpm install
pnpm dev          # open http://127.0.0.1:5173 — simulator by default
```

To connect a backend that speaks the direct wire, copy `gunnflow.config.example.json` to
`gunnflow.config.json` at the repository root and fill in your backend base URL:

```json
{ "upstream": "direct", "url": "<backend base URL>" }
```

Then check it with `pnpm verify` and `pnpm e2e` (after
`pnpm --filter @gunnflow/web exec playwright install chromium`).
