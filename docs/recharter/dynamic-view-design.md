# 동적 뷰 설계 — 배치·lens·sort (2026-10-04, 문답으로 확정)

결정: 지오메트리는 **전환 순간만** 변경 / 집중 표현은 **강조+디테일+공간** /
신호는 **명시 신호만** / 배치는 **전면 재정비** / tier 가중치는 **엔진 상수** /
기록 후 P1부터 착수.

## 단일 파이프라인 (특수케이스 금지)

```
(수신 projection, config, ViewState{lens, sortKey, focus, pins})
    → 관련도 tier 필드 (노드별 0~3)
    → ① 강조·디테일   ② 순서   ③ 공간(크기)
    → 지오메트리는 전환 순간에만 변경 (애니메이션, 핀 존중)
```

모든 화면 변화는 이 파이프라인을 통과한다. 기능별 우회·특수케이스를 만들지 않는다.
"이 노드가 왜 이렇게 보이나"를 한 문장으로 설명할 수 있어야 한다.

## 관련도 tier (엔진 상수, 연속값 아님)

| tier | 조건 (전부 명시 신호·로컬·백엔드 무관) |
|---|---|
| 3 포커스 | 선택·열람 중인 노드, pending intent가 걸린 노드 |
| 2 주변 | 포커스의 수신 엣지 1-hop 이웃 / attention 보유 / 최근 수신 변경(감쇠) / lens 매치 |
| 1 평상 | 나머지 |
| 0 후퇴 | lens가 dim한 것 |

- 숨김 없음, 개수 불변 (§11). tier는 수신 사실+명시 뷰 입력만의 파생 — "뷰" 지위.
- 암묵 이력(체류·빈도) 추적 안 함. 가중치·조건은 엔진 상수 — 필요해지면 그때 config 개방.

## 세 출력

1. **강조·디테일**: 기존 highlight/normal/dim + tier가 노드별 semantic zoom을 한 단계
   올림/내림(표시 label·parts 양). 위치 불변, 즉시 반응.
2. **순서(sort)**: 컨테이너 내부·리스트 표면의 순서 = 사람이 뷰에서 고른 **수신 필드 키**
   (label/state/kind/attention.since)만. **tier는 순서에 관여하지 않는다** — 관련도로
   몰래 재배열하지 않는다. 키 선택은 ViewState(local-only).
3. **공간**: tier 높은 노드가 더 큰 박스(디테일 수용). 크기는 레이아웃 입력이라 전환 시
   자연스럽게 여유가 배분된다.

## 전환 규칙 — 지오메트리가 변하는 유일한 순간

- 토폴로지 변화(stabilize/interim 유지) · lens 변경 · sort key 변경 · 명시 tidy.
- **포커스 전환은 전면 reflow 없이 국소만**: 크기·디테일 변경분을 주변 밀어내기로 흡수.
- 모든 전환은 애니메이션(연속성). 드래그 핀 존중, 핀 해제도 명시 행동.

## P1 — 배치 기반 재정비 (동적성과 독립, 선행)

- ELK 옵션 패스: 간격·컨테이너 패딩·엣지 라우팅·aspect.
- 컨테이너 내 결정적 순서(나중에 sort가 이 입력을 대체).
- 컴포넌트 패킹 개선(행 패킹 → 면적 기반).
- **겹침 금지 불변식**: 어떤 레이아웃 출력도 노드·그룹 겹침이 없음을 테스트로 고정.

## 단계

P1 배치 재정비 → P2 tier 필드 + 강조·디테일 → P3 크기·전환 애니메이션 → P4 sort UI.
P2부터는 단계별 확인 후 진행.

## 경계

전부 Gunnflow view 층. 계약·BFF·adapter 접점 없음 — tier가 수신 데이터로 표현 안 되는
upstream 파생 fact를 요구하게 되는 순간에만 계약 지정(현재 없음). (b) 숨김/필터는 여전히
미결 — 이 설계의 tier 0은 dim이지 숨김이 아니다.
